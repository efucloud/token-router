# 多轮对话与能力编排规格

## 1. 目标

控制台对话窗口在现有私有会话记录和 OpenAI 兼容网关之上，提供可连续工作的多轮
Agent 对话：自动管理上下文、对瞬时故障自动重试，并允许用户按会话启用 Skills 与
MCP 工具。设计参考 QwenPaw 的上下文阈值/退避模型和 opencode 的会话压缩、统一工具
注册边界，但保持 Token Router 当前 Go 控制面 + React 数据面的部署形态。

## 2. 核心原则

- 持久记录与单轮执行分离。用户消息先持久化；模型或工具失败不能丢失用户输入。
- 一个会话同一时刻只执行一个轮次；前端必须防止重复提交和会话切换。
- 每个模型请求只携带“最新摘要 + 摘要后的消息”，不重新注入已被摘要覆盖的历史。
- 重试仅用于尚未产生模型输出的可恢复错误；已产生内容或工具调用后不自动重放。
- Skills 是只读指令资源，按需注入系统上下文，不获得额外执行权限。
- MCP 服务端只由服务端配置；浏览器只能选择已发布能力，不能提交任意命令、URL、
  请求头或环境变量。
- MCP 工具名在模型侧使用 `mcp__<server>__<tool>` 命名空间，避免跨服务冲突。
- 对话正文属于用户私有数据；MCP 参数和结果不写入 Usage Log、Route Attempt 或审计
  摘要。会话历史接口继续按 OIDC 账号隔离。

## 3. 会话状态

会话除标题与模型外，持久化两个选择集：

- `skills`：启用的 Skill 名称数组。
- `mcpServers`：启用的 MCP 服务名称数组。

消息角色继续使用 `system | user | assistant`。自动压缩生成的系统消息以稳定标记
`[token-router:summary]` 开头；加载历史时只选择最后一个该类消息及其后的消息作为有效
上下文。该标记不展示为普通助手气泡，而展示为上下文压缩事件。

## 4. 自动压缩

1. 前端按 Unicode 字符数估算输入 Token，并加入每条消息的固定协议开销。
2. 当有效历史估算值达到 `contextWindowTokens × compactThreshold`，且可被压缩的消息
   数量大于 `compactKeepRecent` 时，在发送新用户消息前触发压缩。
3. 最近 `compactKeepRecent` 条消息原样保留；更早的有效历史交给当前模型生成结构化摘要。
4. 摘要必须保留用户目标、已确认事实、约束、关键决定、未完成事项以及后续继续工作所需
   的工具结果，不得虚构信息。
5. 摘要作为 system 消息持久化，然后再持久化本轮 user 消息。主请求上下文为摘要、保留
   消息和本轮 user 消息。
6. 摘要请求失败时不阻断本轮：使用未压缩的有效历史继续，并在界面显示非阻塞告警。

默认值：上下文窗口 `32768` Token、触发比例 `0.75`、保留最近 `8` 条消息。服务端通过
能力接口下发，前端不自行扩大阈值。

## 5. 自动重试

- 可重试：网络连接失败、HTTP `408/409/425/429/500/502/503/504/529`。
- 不可重试：认证、权限、参数、配额耗尽以及其他确定性 4xx 错误。
- 优先使用响应 `Retry-After`；否则使用带抖动的指数退避。
- 默认最多 `3` 次请求，基础等待 `800ms`，单次等待上限 `8s`。
- 任意内容 delta 或工具调用 delta 到达后，当前请求不再自动重试，避免重复输出或重复
  工具调用。
- UI 显示当前尝试次数与等待状态，但不创建重复的用户消息。

网关已有的多路由容错继续生效；此处的轮次重试解决整次网关请求在响应前失败的问题，
两层策略互不替代。

## 6. Skills

服务端从 `chat.skillDirectories` 白名单目录发现 `SKILL.md`，解析 frontmatter 中的 `name`
和 `description`，并返回可用清单。用户启用后，完整 Skill 内容以带边界的 system 指令
注入每个模型轮次。目录不存在、文件无效或重名时跳过并在能力状态中报告，不影响基础
对话。

首期仅支持服务端本地只读 Skills；Skill 引用的脚本或文件不会被对话窗口自动执行。

## 7. MCP

服务端配置支持：

- `streamable-http`：URL、静态请求头、连接/调用超时。
- `stdio`：可执行命令、参数、工作目录、环境变量、连接/调用超时。

控制面负责连接、初始化、`tools/list` 和 `tools/call`。能力接口只返回服务名、连接状态、
工具名称、说明和输入 JSON Schema，不暴露密钥或进程环境。模型返回工具调用后，浏览器
将调用转发给控制面，结果以 OpenAI `tool` 消息加入同一轮的内存上下文，再由模型继续；
最多执行 `8` 个工具轮次，防止失控循环。

单个工具失败转成结构化工具结果交还模型，不自动重放可能有副作用的工具。MCP 服务不可用
时，其余 Skills、MCP 服务和普通对话仍可继续。

## 8. API 契约

### `GET /api/v1/chat/capabilities`

返回重试/压缩策略、Skills 清单、MCP 服务状态及工具定义。所有字段均为只读发布结果。

### `POST /api/v1/chat/mcp/{server}/tools/{tool}/call`

请求体为 `{ "arguments": object }`。服务端校验 server 和 tool 必须来自已启用配置，执行
后返回 `{ "content": string, "isError": boolean }`。接口沿用 OIDC 鉴权和账号审计边界。

### 会话接口扩展

创建和更新会话接受 `skills: string[]`、`mcpServers: string[]`；列表和详情返回同名字段。
服务端只保存当前已发布名称，未知或重复值被拒绝。

## 9. 对话窗口交互

- 保留左侧历史、中央消息流和固定输入区；在桌面端增加右侧“能力架”，移动端使用抽屉。
- 能力架显示上下文占用、压缩阈值、自动重试状态、Skills 和 MCP 连接/工具数量。
- 发送中锁定模型与能力选择；状态行依次表达“整理上下文 / 正在请求 / 等待重试 /
  正在调用工具 / 正在保存”。
- Ctrl/Cmd + Enter 发送；空输入、无模型或轮次运行中不可发送。
- 普通文本流式展示；工具执行只展示紧凑活动状态，不泄露服务端密钥或环境配置。
- 单项能力故障使用局部状态和非阻塞提示，不能让整个页面失去基础对话能力。

## 10. 验收标准

- 连续发送至少 10 轮后，刷新页面仍能恢复正确顺序和当前能力选择。
- 构造超过阈值的历史后只向主请求发送最新摘要及保留消息，数据库仍保留原始历史。
- 对响应前的 429/5xx/网络错误按策略重试；收到首个 delta 后的失败不自动重放。
- 配置一个示例 Skill 后可在 UI 启用，并能在后续轮次持续生效。
- 配置 MCP 服务后可发现工具、完成一次工具调用并让模型基于结果继续回答。
- 一个失效 MCP 服务不会阻断模型列表、历史加载、普通对话或其他 MCP 服务。
- 官方后端镜像以非 root 用户运行，并预置 Node.js/npm、Python 3/pip，使挂载到容器内的
  Node/Python stdio MCP 服务可直接启动。
- 将 Skill 挂载到 `/efucloud/skills` 后可被发现；将独立 MCP 配置文件挂载到
  `/efucloud/config/mcp.yaml` 后，可通过环境变量加载并覆盖主配置中的 MCP 服务列表。
- 后端测试、前端类型检查、lint 与生产构建通过。

## 11. 非目标

- 本期不提供浏览器任意添加 MCP 地址或 stdio 命令的入口。
- 本期不执行 Skill 附带脚本，不实现 MCP OAuth、resources、prompts 或 sampling。
- 本期不做跨实例分布式会话执行锁；控制台的单浏览器轮次锁与服务端消息顺序事务保持
  当前部署下的一致性。

## 12. 容器部署契约

后端镜像固定使用以下容器内路径：

- `/efucloud/config/config.yaml`：主配置文件，由 ConfigMap、Secret 或只读卷挂载。
- `/efucloud/config/mcp.yaml`：可选的独立 MCP 配置，仅包含 `mcpServers` 数组，适合通过
  Secret 挂载，避免将请求头和 stdio 环境变量烘焙进镜像。
- `/efucloud/skills`：只读 Skill 根目录，可包含多个 `<name>/SKILL.md`。
- `/efucloud/mcp`：stdio MCP 程序、依赖和工作目录的挂载根目录。
- `/efucloud/log`：需要文件日志时使用的可写目录；容器平台优先将日志输出到 stdout。

镜像默认以非 root 用户运行，监听 `9006`，并内置 Node.js/npm 与 Python 3/pip 作为 stdio
MCP 的基础运行时。需要浏览器、系统库或其他语言运行时的 MCP 服务应构建派生镜像，或以
Streamable HTTP sidecar/独立服务部署，不能在运行中的业务容器里临时提权安装依赖。

容器部署支持以下环境变量覆盖：

- `TOKEN_ROUTER_CHAT_SKILL_DIRECTORIES`：使用操作系统路径分隔符连接的 Skill 目录列表；
  设置后覆盖主配置的 `chat.skillDirectories`。官方镜像默认值为 `/efucloud/skills`。
- `TOKEN_ROUTER_CHAT_MCP_CONFIG_FILE`：独立 MCP YAML/JSON 文件路径；设置后读取并覆盖主配置
  的 `chat.mcpServers`。文件不可读或格式错误时服务必须快速失败，不能静默禁用能力。

MCP 密钥不得写入镜像层或非 Secret ConfigMap。Streamable HTTP MCP 推荐部署为同网络的
独立服务；stdio MCP 仅执行服务端预配置的绝对命令，并从只读 `/efucloud/mcp` 卷加载代码。
多副本部署时每个副本各自维护 MCP 会话，MCP 服务自身必须按需处理并发和幂等性。
