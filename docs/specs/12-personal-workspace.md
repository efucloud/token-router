# 对话个人工作区规格

## 1. 目标

`/personal/chat` 为每个已登录用户提供持久、隔离的个人工作区。模型通过内置文件工具在
该工作区内创建、读取、搜索、编辑和删除文件；用户通过右侧“能力架”浏览目录、上传文件
和下载文件。工作区可挂载 PVC，Pod 重启后内容不丢失。

本规格扩展[多轮对话与能力编排](11-conversation-agent.md)，不改变会话正文、Skills 和
外部 MCP 的既有数据边界。

## 2. 核心原则

- 服务端文件系统校验是唯一安全边界。模型提示、内置 Skill 和前端隐藏都不能代替鉴权。
- 用户不能提交用户 ID 或物理目录。所有接口和工具只从已验证的 OIDC 请求上下文取当前
  `account_id`。
- 配置项表示所有用户工作区的共同根目录，不表示任何用户可直接访问该根目录。
- 所有对用户展示、由用户提交或交给模型的路径都是用户目录内的 `/` 分隔相对路径；不
  暴露宿主机路径、PVC 路径、账号 ID 或目录映射键。
- 文件浏览接口与模型文件工具复用同一套路径解析和限制，避免形成权限不一致的第二实现。
- 工作区故障只影响文件 Tab 和内置文件工具，不阻断历史会话、基础对话、Skills 或外部
  MCP。

## 3. 目录模型与生命周期

配置 `chat.builtinTools.workspaceDirectory` 是用户工作区根目录。字段为空或未配置时，
服务在进程运行目录创建 `workspace`。容器部署应在主配置中将其设为
`/efucloud/workspaces`；镜像创建该目录并归非 root 的服务用户所有，Kubernetes 和 Docker
Compose 示例将持久卷挂载到同一路径。

用户目录名为：

```text
sha256("token-router-workspace-v1\x00" + account_id) 的小写十六进制
```

哈希映射保证目录名仅包含固定长度 ASCII，不受 OIDC ID 中的 `/`、`..`、Unicode 或平台
特殊字符影响。哈希不承担鉴权，只用于生成稳定、安全且不泄露账号标识的目录名。

用户首次获取工作区信息、浏览目录、上传文件或调用内置文件工具时，以 `0750` 创建自己的
目录。账号禁用或删除不会自动删除目录，避免不可逆的数据丢失；数据保留与清理由部署方
另行制定策略。

## 4. 服务端隔离规则

每次访问按以下顺序执行：

1. 从请求 `context.Context` 获取已认证的 `account_id`，缺失则拒绝。
2. 解析并校验配置的共同根目录，创建或打开当前用户的哈希子目录。
3. 拒绝绝对路径、NUL 字节及清理后逃逸到 `..` 的路径。
4. 对已存在目标执行 `EvalSymlinks`；对待创建目标逐级解析最近存在的父目录。
5. 解析结果必须仍位于当前用户目录内。指向用户目录外（包括其他用户目录）的符号链接
   一律拒绝。
6. 下载和读取只接受普通文件；目录列表只接受目录；上传文件名只能作为当前目标目录下
   的单个 basename，不能携带路径。

内置 `read_file`、`list_files`、`search_files`、`write_file`、`edit_file`、`apply_patch`
和 `command.workdir` 全部使用当前用户目录作为根。`command` 的进程权限与网络权限不构成
沙箱，仍由 `allowedRoles`、`commandEnabled`、容器安全上下文和 Kubernetes RBAC 控制；
其工作目录隔离不等于命令本身只能访问该目录。

## 5. 配置契约

`chat.builtinTools` 增加或明确以下字段：

| 字段 | 默认值 | 语义 |
| --- | --- | --- |
| `enabled` | `true` | 是否发布个人工作区文件工具和文件接口 |
| `defaultEnabled` | `true` | 新会话是否默认启用内置工具 |
| `workspaceDirectory` | `workspace` | 所有用户目录的共同根路径；相对路径基于进程运行目录 |
| `maxUploadBytes` | `33554432` | 单文件上传字节上限（32 MiB） |
| `maxOutputBytes` | `1048576` | 单次模型文件工具结果上限 |
| `allowedRoles` | `[admin]` | 允许使用 `command` 的角色；不限制个人文件浏览和文件工具 |

配置的共同根目录不存在时由服务创建；创建失败时能力接口返回局部故障，文件 API 返回
服务不可用，服务不得回退到进程当前目录或临时目录。

## 6. API 契约

以下接口均沿用 OIDC 鉴权，不接受 `accountId` 参数。

### `GET /api/v1/chat/workspace?path=<relative-directory>`

列出当前用户目录。`path` 缺省表示根目录。返回：

```json
{
  "path": "reports",
  "entries": [
    {
      "name": "summary.md",
      "path": "reports/summary.md",
      "type": "file",
      "size": 1280,
      "updatedAt": "2026-09-11T10:00:00+08:00"
    }
  ],
  "maxUploadBytes": 33554432
}
```

目录在文件前，同类型按名称自然升序。符号链接不跟随展示为可进入目录；越界符号链接不
暴露目标信息。

### `POST /api/v1/chat/workspace/upload?path=<relative-directory>`

接收 `multipart/form-data` 的单个 `file` 字段，上传到目标目录。文件名取 multipart
basename 并经过平台安全校验；默认覆盖同名普通文件，使用同目录临时文件写入后原子替换。
实际文件字节数受 `maxUploadBytes` 限制，请求体另加固定 multipart 包络余量后限制。成功返回
对应文件条目。

### `GET /api/v1/chat/workspace/download?path=<relative-file>`

以附件形式下载当前用户的普通文件，设置安全的 `Content-Disposition`、
`Content-Type`、`Content-Length` 和 `X-Content-Type-Options: nosniff`。前端通过带
Bearer Token 的 `fetch` 获取 Blob，不把 Token 放入 URL。

错误语义：非法/越权路径为 `400`，目标不存在为 `404`，类型冲突为 `409`，超出上传
限制为 `413`，工作区不可用为 `503`。响应和日志不得包含物理路径。

## 7. 模型指令注入

当会话启用 `builtin` 工具时，在 Skills 指令之后、历史消息之前注入固定 system 指令：

- 文件工具的根目录是当前登录用户的个人工作区；所有路径必须使用相对路径。
- 不得尝试访问父目录、其他用户目录或猜测物理路径。
- 需要交付文件时，将成品写入工作区并在回复中给出相对路径，用户可在“文件”Tab 下载。

该指令是模型行为约束和用户体验提示，不参与授权；即使客户端移除或篡改指令，服务端
仍必须执行第 4 节的隔离规则。

## 8. 能力架交互

右侧能力架头部下方使用两个 Tab：

- **能力**：保留上下文占用、压缩/重试/工具轮次、Skills、MCP 状态与刷新动作。
- **文件**：显示当前位置面包屑、返回上级、刷新、上传入口以及目录列表。目录可进入；
  文件显示大小和更新时间，并提供下载动作。

桌面端继续使用固定右栏，移动端继续使用抽屉式右栏。切换 Tab 不改变会话选择；发送期间
允许浏览和下载，上传按钮在自身请求期间禁用。上传成功后刷新当前目录并给出明确反馈。
下载失败不打开空白页。空目录、首次加载、局部错误和工作区未启用分别使用独立状态。

能力架浮动按钮角标仍只统计已启用的 Skills/MCP，不把文件数计入能力数。

## 9. 验收标准

- 两个不同账号首次访问后得到不同的物理子目录，并且相同账号跨请求稳定命中同一目录。
- 用户 A 无法通过绝对路径、`../`、URL 编码、跨目录符号链接、上传文件名或 Patch 访问
  用户 B 的文件；服务错误不泄露任一物理路径。
- 用户可在模型对话中创建文件，随后无需刷新整个页面即可在“文件”Tab 浏览并下载。
- 用户上传文件后，模型通过 `list_files`/`read_file` 能在同一工作区看到它。
- 内置文件工具对所有已登录用户可用；`command` 仍只对配置角色发布和调用。
- 单文件超过 32 MiB（或配置值）返回 `413`，不会留下完整或临时文件。
- 工作区根挂载 PVC 后，Pod 重建仍可读取原用户文件；未挂载时行为明确取决于部署卷。
- 后端包含目录映射、路径逃逸、符号链接、跨用户、上传限制、浏览与下载测试；前端类型
  检查、lint 和生产构建通过。

## 10. 非目标

- 本期不提供共享目录、跨用户协作、管理员代看用户文件、公开下载链接或对象存储后端。
- 本期不提供浏览器内文本编辑器、文件预览、拖拽移动、批量下载、版本历史或回收站。
- 本期不声称 `command` 是文件系统沙箱；需要强隔离的任意命令执行必须使用独立容器、
  沙箱运行时或受控远程执行服务。
