# 管理控制台

## 1. 技术约束

- React 19、Ant Design 6、Ant Design Pro 6/Umi Max。
- 保留 `@ant-design/charts`、`@ant-design/icons`、`@ant-design/plots`、
  `@ant-design/pro-components`、`antd` 和 `antd-style`。
- 控制面客户端代码由后端 `generate` 直接生成到 `frontend/src/services`，禁止手改生成文件。
- 继续使用现有 OIDC 登录页、回调页、state 校验、过期检查、Bearer 注入和 401 重登录。

## 2. 信息架构

| 页面 | 主要内容 |
| --- | --- |
| 我的工作台 | 本人限额、Token 状态、请求/token 趋势、模型分布和最近调用 |
| 管理员看板 | 全局请求/token、成功率与延迟、渠道健康、故障切换和额度风险 |
| 模型与路由 | 统一模型目录、能力标签、发布状态、显式上游路由 |
| 供应商资源 | Provider、地址、凭据已配置状态、优先级/权重、健康与 cooldown |
| API Key | 创建、一次性复制、模型范围、限额、过期、禁用和删除 |
| 模型对话 | 使用当前 OIDC 身份选择统一模型，保存、切换和管理私有对话记录 |
| 用户与限额 | OIDC 用户、角色、token/请求限额和累计用量 |
| 用量日志 | 请求、模型、用户、渠道、状态与 Route Attempt 详情 |
| 操作审计 | 管理员写操作的操作者、资源、结果、Request ID 和来源 IP |
| 模型演练 | 选择统一模型执行临时诊断，展示 TTFT、总耗时、Token、最终渠道和尝试链 |

角色决定菜单可见性，但所有数据范围仍由服务端裁剪。

普通用户登录后在左侧显示“我的工作台”和“API Key”，“模型对话”作为顶部快捷入口，
不增加“个人控制台”父级分组。进入模型对话后隐藏 ProLayout 左侧菜单，页面内部使用
Codex 风格的会话记录栏与主对话区。
管理员同时是普通用户，登录后默认进入个人工作台，并可使用模型对话和自己的 API Key。
只有点击右上角用户菜单中的“系统控制台”才切换到系统管理区；进入后导航只显示系统管理
菜单，右上角提供“个人控制台”用于返回。非管理员不渲染系统控制台入口，直接访问系统
路由时展示 403 页面。个人区与系统区的菜单不在同一个导航中混排。

系统控制台不是单一页面，左侧导航至少包含以下独立菜单：

- 运行概览
- 模型管理
- 供应商管理
- 渠道管理
- 路由策略
- 模型演练
- 用户与额度
- 用量日志
- 路由尝试
- 操作审计

## 3. 用户工作台

所有 OIDC 用户登录后的默认首页为“我的工作台”，只展示本人数据：

- 用户级 token/请求限额、已用量、剩余量和使用进度；无限额时明确显示“不限制”。
- 本人 active、disabled、expired API Key 数，以及最近到期的 Token。
- 所选时间范围内的请求数、成功率、输入/输出/总 token 和 P95 延迟。
- 请求与 token 趋势、统一模型使用分布、错误分类分布。
- 最近调用列表：时间、Token 前缀、模型、状态、token、耗时和请求 ID。
- 接近 80% 限额、Token 即将过期或全部 Token 被禁用时显示行动提示。

用户工作台不展示其他用户、全局渠道凭据、全局排名或金额信息。

## 4. 管理员运行看板

仅 `admin` 可见，用于判断网关整体运行状态：

- 全局请求数、成功率、输入/输出/总 token、平均/P95 延迟、活跃用户和活跃 Token。
- 请求/token/错误趋势，以及按统一模型、用户和渠道的用量分布。
- healthy、cooldown、disabled、配置异常渠道数量和当前明细。
- 上游尝试数、故障切换请求数、切换成功率和高失败率路由。
- 接近或耗尽限额的用户/Token、即将过期 Token 和异常流量变化。
- 最近失败请求与 Route Attempt 摘要，可跳转到用量日志详情。

管理员可切换 `24h`、`7d`、`30d`，但看板不承担配置编辑；卡片和表格跳转到对应
管理页面完成处理。

## 5. 视觉与交互

视觉严格沿用 Ant Design Pro 默认布局和配色：保留顶部 Header、左侧菜单和右上角语言及
用户区，采用原生页面容器、卡片、表格与表单。避免自定义背景、营销大图、渐变英雄区和
价格/余额等消费平台措辞。

- 运行状态用文字和颜色共同表达，不能只依赖颜色。
- 高风险操作使用确认对话框；优先提供禁用而非删除。
- Token 创建成功使用一次性密钥对话框，关闭前提示用户完成复制，之后不可再次查看。
- 模型对话使用当前 OIDC Token，不要求用户输入 API Key；左侧提供当前用户私有的历史
  会话、新建、搜索、切换和删除能力，首条消息自动生成标题，模型回复流式结束后保存。
- 页面不得接收上游供应商密钥；Usage Log、Route Attempt 与审计不得保存对话正文。
- 密钥字段始终为密码输入；编辑渠道时留空代表不修改。
- 渠道测试成功后可多选发现模型并导入；新模型和路由默认启用，已有记录保持原启停状态。
- 模型管理按渠道使用 Tab 分组；同步时清理该渠道已失效的路由，仅删除无其他渠道引用的
  孤立模型，渠道连接失败时不得修改数据库。
- 路由策略同样按渠道使用 Tab 分组，并保留全部路由总览；在渠道 Tab 中新建路由时默认
  选择当前渠道。
- 表格筛选写入 URL query，支持刷新和分享当前视图。
- cooldown、额度耗尽、禁用和配置错误应给出可执行的原因说明。
- 模型演练结果在同页展示，提示词和模型输出不得进入浏览器持久存储。

## 6. 指标展示规则

两个 Dashboard 默认展示最近 24 小时与前一周期对比。共同指标包括：

- 成功/失败请求数和成功率。
- 输入、输出和总 token。

模型和渠道健康只属于管理员看板；用户工作台只显示本人的 Token 和限额。活跃 Token
与限额风险也必须按各自数据范围聚合。

图表只表达趋势和分布，不展示金额。无数据时提供接入模型、配置路由、创建 Token 的
引导，不使用虚构数据。

## 7. 响应式和可访问性

- 桌面端优先，最小支持 1280px 的高密度运维场景；窄屏可折叠菜单和次要列。
- 键盘可访问主要操作，表单有明确 label，错误提示与具体字段关联。
- loading、empty、error、permission denied 状态均需独立设计。
