# 企业能力路线

## 1. 参考边界

本规格对照 new-api 与 TokenHub，但不复制它们的产品形态。Token Router 的唯一定位是
企业内部统一 AI 模型聚合与分发网关，Token 归属于用户，使用者可将它用于任意获准的
内部用途，不引入项目、团队、计费账户或商业售卖边界。

| 参考能力 | Token Router 取舍 |
| --- | --- |
| 多供应商、统一模型名、模型映射 | 核心能力，保留 |
| 优先级、权重、重试、故障切换 | 核心能力，保留 |
| Token 模型白名单、过期、禁用、限额 | 核心能力，保留并强化 |
| 渠道测试、模型发现、健康与冷却 | 核心运维能力，保留 |
| 请求日志、Route Attempt、管理审计 | 核心治理能力，保留 |
| OpenAI/Anthropic/Gemini 协议转换 | 分阶段接入，不承诺所有供应商私有扩展 |
| 内容安全、敏感信息检测 | 企业增强能力，按可插拔策略实现 |
| RPM、TPM、并发与 IP 白名单 | 企业准入能力，保留 |
| 项目、团队、成本中心 | 排除；不得成为 Token 使用边界 |
| 价格、余额、充值、支付、订阅、兑换码 | 排除 |
| 供应商账单、对账、利润或销售统计 | 排除 |
| 插件市场 | 排除；只保留受控的内置 Adapter 注册边界 |

## 2. 当前能力基线

### 数据面

- `GET /v1/models`、`POST /v1/chat/completions`、`POST /v1/responses`、`POST /v1/embeddings`。
- OpenAI Compatible 上游、普通响应、Chat NDJSON 与 Responses SSE 流式转发。
- 统一模型到上游模型的显式映射。
- 最高优先级候选内的加权选择、失败重试、故障切换和渠道冷却。
- 用户与 API Key 双层总 Token/成功请求次数限额，事务预留和幂等结算。
- API Key IP/CIDR 白名单、RPM、TPM 和最大并发准入，使用持久化分钟桶和过期租约。
- Usage Log 和逐次 Route Attempt，不保存请求/响应正文。

### 控制面

- OIDC 登录和 `admin` 服务端权限校验。
- 统一模型、Provider、渠道、模型路由的增删改查。
- 渠道连接测试、上游模型发现预览、延迟与最近健康结果。
- 从发现结果选择模型，幂等创建默认启用的统一模型和渠道映射。
- 用户角色、启停和用户聚合限额管理。
- API Key 创建、模型范围、过期、启停和删除，明文只显示一次。
- 用户 Dashboard 与管理员 Dashboard 数据范围隔离。
- 用量查询、请求详情和 Route Attempt 查询。
- 管理写操作审计和独立审计查询页面，正文与敏感字段值不入库。
- 模型、Provider、渠道和路由配置使用单调版本号乐观锁，过期编辑返回 409。
- 独立 `/livez` 与 `/readyz` 探针；就绪状态覆盖数据库、关键迁移表和网关主密钥。
- 冷却渠道仅能通过单实例半开探测恢复；定时与手工探测共用状态分类器。
- 管理员模型演练返回 TTFT、总耗时、Token、Request ID、最终渠道和尝试链，正文不持久化。

## 3. P1：达到可生产运营

以下能力优先于继续增加页面数量：

1. （已完成）API Key 的 RPM、TPM、最大并发和 IP/CIDR 白名单，返回标准 `429`、
   `Retry-After` 和限流响应头。
2. （已完成）渠道主动健康检查、单实例半开恢复，以及手工测试和定时探测共用分类器。
3. （已完成）从渠道发现结果选择并导入上游模型，导入是幂等操作，不自动发布统一模型。
4. （已完成）OpenAI Responses API，覆盖普通、流式和工具调用透传；明确拒绝首版不支持的
   后台任务。
5. （已完成）管理操作审计：操作者、动作、资源、变更字段名、结果、时间和 Request ID；
   请求正文和敏感字段值永远不写入审计表。
6. （已完成）配置版本号和乐观锁，避免多个管理员相互覆盖模型、渠道和路由配置。
7. （已完成）模型演练场诊断：TTFT、总耗时、Token、Request ID、最终渠道与尝试链；
   只有管理员能看到上游内部信息，提示词和输出不持久化。
8. （已完成）就绪探针检查数据库、迁移状态和加密主密钥；存活探针不依赖外部供应商。

## 4. P2：协议与治理扩展

- Anthropic Messages 与 Gemini 原生协议 Adapter，支持文本、图片、工具调用和流式事件。
- 关键词、正则和常见凭据/隐私数据检测，动作支持 `audit`、`mask`、`block`。
- 请求级 OpenTelemetry Trace 导出；重新设计独立的运维包，不恢复已删除的
  `pkg/metrics`。
- 告警规则和 Webhook/邮件通知：渠道连续失败、额度接近阈值、错误率突增。
- 用量 CSV 导出与只读分析凭证；不得复用管理员会话或模型调用 Token。
- 可选 Redis 用于多实例 RPM/TPM/并发租约和路由缓存；MySQL 继续作为持久账本。

## 5. 可靠性约束

- `400/401/403` 等确定性错误默认不跨渠道重试；网络错误、`408`、`429` 和 `5xx`
  依据策略重试。
- 流式响应首字节已经发给客户端后不得切换上游。
- 手工禁用的渠道不能被健康检查自动启用；冷却渠道只通过半开探测恢复。
- 渠道连接测试不得在响应、日志或错误信息中泄露 API Key。
- 模型发现只更新观测结果，必须由管理员显式导入和发布。
- 所有准入计数在调用上游前完成；失败和取消必须释放未使用的预留与并发租约。
