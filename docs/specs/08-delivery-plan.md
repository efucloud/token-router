# 交付计划

## 1. 实施顺序

### 阶段 A：领域与安全基础

- Account 双层限额字段、核心表结构和迁移。
- `gateway` 配置、AES-GCM 上游凭据存储。
- API Key 安全生成、摘要与认证。
- 修正管理接口服务端角色校验。

### 阶段 B：控制面

- 模型、Provider/Channel、路由和用户 Token 管理 API。
- 用户角色与限额 API。
- 用量列表、汇总和 Route Attempt API。
- 生成前端 `src/services`。

### 阶段 C：数据面

- `/v1/models`、chat completions、Responses、embeddings。
- 模型范围、双层限额预留/结算。
- 优先级/权重路由、故障切换和 cooldown。
- 普通 JSON、Chat NDJSON、Responses SSE、Usage Log 和 Route Attempt。

### 阶段 D：管理控制台

- 用户工作台、管理员运行看板、模型对话、模型/路由、供应商资源、Token、用户限额和用量页面。
- 按角色控制菜单和操作，并处理所有空/错/加载状态。

### 阶段 E：企业运营增强

- 已完成 RPM/TPM/并发/IP 准入、主动健康检查和半开恢复。
- 已完成 Responses API、管理审计、模型发现导入、配置版本乐观锁、管理员模型演练及部署探针。
- 详细范围与优先级见[企业能力路线](10-enterprise-capabilities.md)。

## 2. MVP 验收标准

1. OIDC 用户可以进入控制台，后端按数据库角色执行权限检查。
2. 管理员可以创建统一模型、至少两个资源，并配置到不同上游模型名的显式路由。
3. 未配置路由或禁用的模型不出现在 `/v1/models`。
4. 用户可创建只显示一次明文的 `tr_` Token，并调用 models、chat、Responses、embeddings。
5. Token 模型白名单生效，越权模型返回稳定的 403/404 风格数据面错误。
6. 禁用渠道后不再被选择；网络错误、5xx 和可重试 429 可以故障切换。
7. 用户级或 Token 级次数/token 限额耗尽时返回 OpenAI 风格 429。
8. 并发请求不能绕过限额，失败请求正确释放预留，重复结算不重复扣减。
9. 普通和流式调用均生成不含敏感正文的 Usage Log 与 Route Attempt。
10. 后端测试、前端 lint/类型检查/生产构建和 `git diff --check` 通过。
11. 普通用户 Dashboard 只能看到本人数据，管理员 Dashboard 能看到全局运行与风险数据。
12. 用户可使用当前 OIDC 身份选择统一模型完成网关对话，并保存、恢复、搜索和删除本人
    的对话记录。
13. 管理员可以从渠道发现结果选择模型导入；重复导入不产生重复模型或路由，新模型默认
    不发布。
14. 所有管理员写操作产生不含请求正文和敏感字段值的审计记录，并可在系统控制台查询。
15. 冷却渠道到期后必须先通过半开探测才能恢复生产流量，且同一时间只有一个半开探测。
16. 管理员可运行不持久化正文的模型演练，并查看 TTFT、Token、最终渠道和尝试链。

## 3. 测试重点

- AES-GCM nonce、错误主密钥和密文篡改。
- Token 随机性、前缀、摘要查找、禁用和过期。
- SQLite/MySQL 下限额并发预留、成功/失败/估算结算与过期回收。
- 权重仅在最高优先级组生效，失败路由不重复尝试。
- 响应开始前可重试、开始后不可重试；客户端断开取消上游。
- 任何管理响应和日志均不泄漏明文凭据或 payload。

## 4. 后续版本

- 精确 tokenizer 与按分钟/小时滑动窗口 RPM/TPM。
- 分布式并发限制与更丰富的用户/Token 限额策略。
- 多实例共享的分布式熔断状态与探测协调。
- Redis 路由缓存与高并发配额预留。
- Anthropic 与 Gemini 原生协议适配。
- Prometheus 和 OpenTelemetry（以新的运维包实现，不恢复已删除的旧 `pkg/metrics`）。
- 稳定 Provider Adapter 注册表和受控扩展，但不引入商业插件市场。

## 5. 变更规则

- 全局定位、非目标或平面边界变更时更新总规格和对应子规格。
- 单一领域/API/页面的设计只更新相应子规格，避免总规格膨胀。
- 新能力进入开发前先明确属于 MVP 或后续版本，并补充可验证的验收条件。
