# 产品范围

## 1. 目标

Token Router 为企业内部应用提供统一、稳定、可治理的 AI 模型访问入口：

- 屏蔽不同供应商的地址、凭据和可用性差异。
- 通过统一模型名控制企业允许使用的模型能力。
- 通过 OIDC 用户和其 API Key 明确人员与调用凭据的访问边界。
- 对用户和 Token 设置 token 总量及成功请求次数限额。
- 记录不含敏感正文的用量与选路审计信息。

## 2. 用户与角色

控制台不提供密码登录或公开注册，人员身份全部来自企业 OIDC。

| 角色 | 能力 |
| --- | --- |
| `admin` | 管理全部资源、角色与限额，查看全部用量 |
| `edit` | 管理模型、渠道和路由，管理自己的 Token，查看全部用量 |
| `view` | 查看运行配置和全局汇总，仅管理自己的 Token |
| `none` | 管理自己的 Token，查看自己的限额与用量 |

权限最终由后端校验；前端菜单隐藏只改善体验，不构成安全边界。

## 3. MVP 范围

- 企业 OIDC 控制台认证。
- 模型目录、Provider、Provider Resource（控制台称“供应商资源”或“渠道”）。
- 显式模型路由、优先级、权重、5xx/网络失败切换和短时 cooldown。
- API Key 创建、一次性展示、禁用、过期和模型白名单。
- 用户级和 API Key 级 token 总量/成功请求次数限额。
- OpenAI 兼容的 models、chat completions、embeddings；chat 支持 HTTP 分块 NDJSON。
- 请求用量日志与逐次 Route Attempt。
- 当前用户私有的模型对话与消息历史。
- SQLite 与 MySQL。

## 4. 明确非目标

- 价格、倍率、余额、充值、支付、订阅、账单和财务对账。
- 兑换码、邀请码、邀请返利和公开用户注册。
- 面向互联网售卖 API 的租户与营销体系。
- 在 Usage Log、Route Attempt 或操作审计中保存提示词、请求正文或响应正文。用户主动
  创建的私有对话记录不属于此限制。
- MVP 阶段的完整 Provider 插件市场和插件生命周期。
- MVP 阶段的 Anthropic/Gemini 原生下游协议。

## 5. 术语

- **统一模型**：企业内部稳定发布的模型名。
- **Provider**：一种上游接入类型或供应商定义。
- **Provider Resource/Channel**：可被调度的一套地址、凭据、区域和容量。
- **Model Route**：统一模型到资源及上游模型名的显式映射。
- **API Key**：用户创建并直接归属于该用户的数据面调用凭据，不等同于 OIDC Token；
  网关不限制该 Token 被用于哪个内部项目或应用。
